# AngelScript 空闲门墙钟预算修复与复测尝试

> 已完成修复和一次预定六对复测：12/12空闲门通过，612条统计记录通过校验。比上一轮负载显著降低，但dispatch仍不确定，Vector/Color不支持AS专属收益。修复不涉及生产优化、VM或原17项基准算法；旧实验及其运行器快照保持原样，新证据独立保存。

## 修复了什么

旧运行器用60次“睡眠1秒＋同步PDH采样”代替60秒预算，导致实际等待明显超出预期；仅把循环换成截止时间还无法限制卡住的PDH调用。

新版[运行器](<../../modules/angelscript/tests/interleaved_ab_benchmark.py>)做了以下改变：

1. **一个绝对单调时钟截止时间。** 睡眠、监控初始化等待、采样等待共享60秒预算；每个监控请求另有3秒上限，取两者剩余时间的较小值。不再以样本数量近似墙钟时间。
2. **隔离慢监控。** Windows DLL加载、PDH初始化和采样都在自有子进程中进行。父进程使用带期限的IPC等待；超时请求将监控器标记为不可复用，不能把迟到结果误当成下一次采样。清理只操作该自有子进程。
3. **低负载必须是有效的新数据。** 每个门重置CPU差分基线；CPU值有限且在0–100%，平均窗口不超过3秒，收到时CPU读数年龄不超过2秒，完成时间早于截止时间。缺失、NaN、过时、迟到结果均不能满足空闲条件；连续3个有效样本CPU<25%才通过。
4. **失败就停止，而不是继续测。** 默认第一个失败门结束整次尝试，保存 `idle_unavailable` 状态并返回退出码2。未完成矩阵不生成完整配对统计；保留已有遥测、部分样本和原始日志，不自动补跑或替换。
5. **运行期间也限制监控等待。** 基准进程存活检查及采样共享其超时截止时间，避免监控无限阻塞对子进程的管理。
6. **保留身份和状态证据。** 可用旧manifest核对A/B实际引擎、依赖、项目和实际加载的C# Debug组件；运行结束再验证，保存运行器快照、门耗时/超出量、清理耗时及明确结果状态。

[分析器](<../../modules/angelscript/tests/interleaved_ab_analysis.py>)识别中止实验，只汇总环境与门结果，不把空数据或部分数据解释成性能比较；分析输出也是创建式写入。

### 不能保证的部分

Windows及Python并非硬实时系统：父进程可能在截止时间后才被调度恢复。实现能限制主动等待、拒绝超期通过，并记录实际 `overshoot_s`，不能保证任意系统负载下精确在60.000000秒返回。worker进程创建、结果落盘、worker清理及前后哈希校验是门外开销，分别记录相关耗时，不能混作60秒门预算。

PDH频率仍只是聚合代理，不是逐核有效频率；监控子进程自身仍有开销，尚未量化监测对基准的扰动。门通过也不证明之后整个基准持续空闲或亲和性核心独占。

### 派发与几何：结论没有被噪声反转

- **Dispatch：仍不确定。** 配对耗时下降2.71%，95%区间0.915–1.011跨1；GD对照0.989、归一化0.985。没有支持>5%改善或>5%回退的证据，不能证明绝无回退。B仍约为GD耗时的1.57倍。
- **Vector/Color：原始耗时约下降5.08%/5.13%，但不满足预定“整个区间低于0.95”规则。** 区间分别0.926–0.958及0.935–0.956；二者原始区间虽低于1，不应因此换判据宣布已证实>5%收益。
- **GD对照改善更多：** Vector GD比0.884、Color GD比0.920；归一化1.070/1.029。因此不能把原始5%认作AS专属改进。归一化>1也不等于证实AS代码回退，可能包含不同语言对环境/构建的不同响应。
- **几何没有追平GD：** B Vector为62.67ns、GD为12.78ns（4.91倍）；Color为62.61ns、GD为13.39ns（4.68倍）。本轮不足以支持启用POD实验或牺牲生命周期语义。

### 其他组合收益

Array/Dictionary/Array methods/String/Packed的配对耗时下降分别为 **85.38% / 92.08% / 82.35% / 70.14% / 27.95%**，大幅收益仍然复现。本轮原始分类仍为10项改善信号、0项支持回退、7项不确定，但成员与旧实验不同（例如calls/class不再满足>5%改善区间规则）。这体现环境/对照的重要性，不是生产代码在两次实验间发生了变化。

B数值上仍为7/17项不慢于GD，另10项慢于GD；batch_sum虽有组合收益，仍为GD耗时的1.14倍。typed_vec2的优势仍是原有批量路径，不能当作VM逐元素公平比较。
