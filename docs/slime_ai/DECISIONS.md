# Decisions

1. **P00 source authority.** The local checkout matched the remotely documented hash, but the local compiler, Python import collision, and actual output binary were verified independently. The source checkout was not reset.
2. **Transport 1.0.** Use private UTF-8 newline JSON over one child process, capped at 1 MiB per control frame. The first service is deterministic fake mode, visibly identified. Native code owns revisions, approval, mutation, and journal state.
3. **Editor boundary.** Slime AI sources enter through one editor-only SCons hook and one built-in plugin registration. No export-template dependency or static startup side effect is intended.
4. **P03 scope.** One loaded native scene per changeset. Undo history belongs to the editor session. Process-crash reconciliation is separate and must refuse a later human edit. Cross-file atomicity and power-loss durability are not claimed.
5. **Fixtures.** Keep small source fixtures immutable; copy before mutation. No generated scripts or imported plugins are part of P00–P03.
6. **Fake service launch.** For this local developer build, the fixed trusted script is `tools/slime_ai/agent_service/src/main.ts`, launched by Node 24 with type stripping. A missing script/runtime must leave the editor usable. Packaging for broader users remains P10.
7. **Native command revision 1.1.** The fake service still speaks wire version 1.0. P03's native operation catalog adds safe position/visibility edits, renaming, and removal with a single-operation preview boundary. Larger operation arrays are explicitly unsupported until atomic undo/recovery tests exist.
8. **Read-only inspection boundary.** Project enumeration is limited to `res://` root files, scene pages default to 128 nodes with a bounded depth, and object reads use native Node2D/Node3D accessors plus Sprite2D texture identity. Custom script getters and texture contents are excluded. Only a small explicit context manifest goes to the fake child; unsaved scene contents stay local unless a future user action attaches them.
9. **Crash reconciliation.** Prepare a checksummed journal record before the editor-thread effect and append confirmation after it. The injected crash saves the effect and terminates the process before confirmation. Restart reports `present_unconfirmed` and refuses replay of the recorded ID; it does not silently revert a possibly newer human edit. The journal flush is a process-crash measure, not a power-loss guarantee.
10. **Save result is a real result.** `EditorNode` and `EditorInterface::save_scene()` now return the underlying resource saver error. The Windows safe-save close/replace result is checked before reporting success. The real exclusive-lock fixture is the acceptance proof; the separate deterministic injection remains a regression aid only. Application and persistence are displayed as separate facts.
11. **Unresolved scope lock.** A prepared journal operation blocks new automated proposals in the same scene even with a fresh request ID. Duplicate status of the recorded ID remains read-only. Explicit resolution binds the journal operation, scene path, reviewed effect, and current revision, and records `resolved_without_replay`; it never invents an acknowledgement or rewinds newer edits.
12. **Wire 1.1 for P04.** The 1.0 fake protocol remains supported for P03. P04 uses versioned run/event frames and normalized `text_delta`, `tool_call_ready`, `usage_update`, `turn_completed`, and `turn_failed` events. Tool arguments are buffered, parsed, validated, and released only after a successful complete provider response. Provider-turn completion is not task completion.
13. **One provider and finite service loop.** OpenAI Responses is the first live adapter, with an explicit model and `call_id` continuation; no model name is guessed. Fake and OpenAI responses pass through the same event/host tool policy. One service run and one call are active at a time; local request/attempt/tool/deadline bounds apply. Native IDs, grants, revisions, and journal writes remain editor-owned.
14. **Credential and consent boundary.** Use a user-scoped Windows Credential Manager target `SlimeEngine/OpenAI`; a development environment fallback requires `SLIME_AI_DEV_CREDENTIAL_FALLBACK=1`. The editor refuses to launch the service if its process inherited `SLIME_AI_OPENAI_API_KEY`, to avoid forwarding that secret to project children. Service startup stays offline. A live run requires an explicit model and one-run editor authorization, with context limited to a selected scene summary plus explicit bounded tool reads.
15. **P04 intent and tool scope.** Discuss cannot preview or write. Propose can create a nonmutating native preview. Execute requires a visible trusted transition, current revision, and the existing native grant/apply path. The P04 model-facing preview schema permits only one `create_child` operation; native P03 operations remain available through their existing local interface but are not expanded into untested model capabilities.
