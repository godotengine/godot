# Decisions

1. **P00 source authority.** The local checkout matched the remotely documented hash, but the local compiler, Python import collision, and actual output binary were verified independently. The source checkout was not reset.
2. **Transport 1.0.** Use private UTF-8 newline JSON over one child process, capped at 1 MiB per control frame. The first service is deterministic fake mode, visibly identified. Native code owns revisions, approval, mutation, and journal state.
3. **Editor boundary.** Slime AI sources enter through one editor-only SCons hook and one built-in plugin registration. No export-template dependency or static startup side effect is intended.
4. **P03 scope.** One loaded native scene per changeset. Undo history belongs to the editor session. Process-crash reconciliation is separate and must refuse a later human edit. Cross-file atomicity and power-loss durability are not claimed.
5. **Fixtures.** Keep small source fixtures immutable; copy before mutation. No generated scripts or imported plugins are part of P00–P03.
6. **Fake service launch.** For this local developer build, the fixed trusted script is `tools/slime_ai/agent_service/src/main.ts`, launched by Node 24 with type stripping. A missing script/runtime must leave the editor usable. Packaging for broader users remains P10.
7. **Native command revision 1.1.** The fake service still speaks wire version 1.0. P03's native operation catalog adds safe position/visibility edits, renaming, and removal with a single-operation preview boundary. Larger operation arrays are explicitly unsupported until atomic undo/recovery tests exist.
8. **Read-only inspection boundary.** Project enumeration is limited to `res://` root files, scene pages default to 128 nodes with a bounded depth, and object reads use native Node2D/Node3D accessors plus Sprite2D texture identity. Custom script getters and texture contents are excluded. Only a small explicit context manifest goes to the fake child; unsaved scene contents stay local unless a future user action attaches them.
9. **Crash reconciliation.** Prepare a checksummed journal record before the editor-thread effect and append confirmation after it. The injected crash saves the effect and terminates the process before confirmation. Restart reports `present_unconfirmed` and refuses replay of the recorded ID; it does not silently revert a possibly newer human edit. The journal flush is a process-crash measure, not a power-loss guarantee.
